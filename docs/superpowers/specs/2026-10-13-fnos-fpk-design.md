# Qingye standalone fnOS FPK

Approved scope: user explicitly requested a standalone fnOS application, supplied fnOS 1.2.0800 and Intel i5-6500 (x86-64), then said "do it". Existing Windows/Mac desktop artifacts stay intact.

## User experience
Install one FPK using fnOS App Center. Open Qingye in a fnOS desktop iframe via the official unified gateway. No separate computer client, Docker setup, account registration or public service is required. Administrator-only first release: allUsers=false plus server-side X-Trim-Isadmin check; normal NAS users receive 403. Choose files from NAS-authorized directories or upload local files into the application's shared inbox. Choose an existing authorized output folder; original files are never overwritten. Existing PDF/image/Office/audio/video operations, quality options, progress, cancellation, merge ordering and results remain available. Download results or see their NAS paths. Startup settings explain directory authorization and restart after changing it. This release does not add remote MCP, advertisements, OCR, or mobile applications.

## Boundaries and packaging
FPK appname qingye, x86 architecture, target fnOS 1.2.0800; minimum version declared 1.2.0 as the target family, explicitly unverified on hardware until device testing. Official fnpack builds the package. manifest, config/privilege, config/resource, app/ui/config and cmd scripts follow official docs. app/ui/config registers gatewayPrefix /app/qingye and gatewaySocket app.sock, admin-only iframe. No TCP listener in production. Native Linux Node, Sharp/libvips, MuPDF, FFmpeg, LibreOffice and CJK fallback font are bundled; Docker is used only as a build/test environment. Debian 12 Linux amd64 baseline, dependent libraries included and checked in a clean container. No host apt installs, root runtime, arbitrary command execution, or dependency on desktop Electron.

## Runtime
fnos/server.mjs uses the existing catalog and JobService. A global busy guard serializes all conversion submissions; each job is bound to gateway user UID so one administrator cannot read/cancel another administrator's jobs or download their results. Authentication requires UID and isadmin=true from the system gateway via a permission-restricted Unix socket. JSON mutations require a custom request header; cross-site requests with mismatched Origin are rejected. No CORS. Static assets have an explicit whitelist; renderer adapter replaces Electron IPC with same-origin requests under /app/qingye. No browser-supplied identity is accepted in JSON.

Authorized roots come only from TRIM_DATA_SHARE_PATHS and TRIM_DATA_ACCESSIBLE_PATHS, refreshed on process start. All filesystem APIs canonicalize and enforce root boundaries; symlink escapes are denied, including again at execution/export. Private configuration/runtime folders are never roots. Directory listings hide dotfiles and inaccessible children. Outputs downloads are restricted to that user's recorded job outputs plus current directory authorization. Uploads stream to a unique private partial file inside the shared inbox, have operation-specific size limits, clean up on failure/disconnect, then atomically become collision-free source files. No document text is interpreted as commands. Uploads preserve originals until user removes them with fnOS file management.

cmd/main starts exactly its own PID, waits for socket readiness and reports errors through TRIM_TEMP_LOGFILE; stop sends SIGTERM to only the recorded, identity-checked process. Server shutdown cancels the active job and waits for worker/child cleanup. Crashes do not automatically retry jobs. Startup sweeps only app-owned upload partial files; temporary conversion folders follow the shared engine's normal cleanup. Upgrade preserves share and data directories. Uninstall scripts never delete user source or result files. Persistent logs are bounded/rotated; no document contents are logged. One task at a time; hardware acceleration excluded for this release.

## Validation and delivery
Tests: gateway auth/admin checks, CSRF, own-job access, path traversal/symlink denial, list/select/upload, streaming limits, valid conversions and results, cancellation, shutdown/restart, start/stop/status shell lifecycle. Browser integration test through a local simulated gateway against the same socket confirms UI. Clean Linux amd64 container verifies PDF/image/media and Chinese DOCX/XLSX/PPTX with real bundled binaries. FPK manifest/payload/architecture/font parity and official fnpack structure checks. Source archive, SHA256, Chinese install/troubleshooting instructions. Report separately what was verified locally and what requires actual fnOS device; no claim that system gateway/ACL/App Center integration is hardware-tested.
